## 工作流概览

**用途**： 验证代码与应用镜像，仅在校验成功后将同一镜像发布到 GitHub Container Registry（GHCR），并在 `main` 推送的真实发布后触发一次生产部署钩子。
**触发事件**： `main` 分支推送、`v*` 标签推送、拉取请求、手动触发。
**目标环境**： Linux AMD64 容器；校验与发布不触碰生产。只有 `main` 推送的真实发布会调用部署钩子，由外部部署平台重建生产容器。

部署钩子是**外部平台的生命周期触发**，不是本工作流自己执行替换：它不停止容器、不运行迁移、不验证健康、也不恢复入口。生产应用的迁移由应用启动时自动执行。

## 执行流程图

```mermaid
graph TD
    Trigger[触发] --> Verify[代码校验]
    Trigger --> Image[构建镜像]
    Image --> Artifact[临时镜像产物]
    Verify --> Gate{两项成功且允许发布}
    Artifact --> Gate
    Gate -->|是| Publish[发布 GHCR 标签与 digest]
    Gate -->|否| End[不发布]
    Publish --> Hook{main 推送且钩子已配置}
    Hook -->|是| Deploy[调用部署钩子]
    Hook -->|否| Skipped[不部署]
```

## 任务与依赖

| 任务名称 | 用途 | 依赖 | 执行环境 |
| --- | --- | --- | --- |
| verify | 类型检查、静态检查、单元测试、应用构建 | 无 | Linux 托管运行器 |
| image | 构建运行镜像及来源元数据 | 无，与 verify 并行 | Linux AMD64 构建环境 |
| publish | 发布 image 的原始产物，不重新构建 | verify、image 均成功 | 具有包写入权限的 Linux 运行器 |
| deploy | 调用外部部署钩子触发生产发布 | publish 成功 | Linux 托管运行器，无仓库权限需求 |

## 需求矩阵

### 功能需求

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| REQ-001 | 所有触发均验证代码与镜像构建 | High | 失败的校验或构建阻止发布 |
| REQ-002 | 仅主分支和版本标签允许发布 | High | PR、其他分支的手动运行均不登录或推送 GHCR |
| REQ-003 | 可追溯到源码提交 | High | 镜像含完整提交 SHA 标签、来源标签和同一 SHA 的诊断构建标识 |
| REQ-004 | 分支与版本标签互不污染 | High | main 发布 main/latest；版本发布对应 v 标签，不能改写 latest |
| REQ-005 | 发布同一构建产物 | High | 发布阶段只加载、重新标记并推送，不能重新编译 |
| REQ-006 | 支持不可变部署引用 | High | 成功运行摘要包含已推送的镜像标签和仓库 digest |
| REQ-007 | 部署晚于镜像可用 | High | 部署任务依赖发布成功，绝不与镜像推送并行或早于推送 |
| REQ-008 | 只为主分支推送部署 | High | `v*` 标签、PR、手动运行均不调用部署钩子 |
| REQ-009 | 每次真实发布至多触发一次部署 | Medium | 单次运行只发起一次成功的钩子调用，不因非 2xx 而自动重试 |

### 安全需求

| ID | 需求 | 实现约束 |
| --- | --- | --- |
| SEC-001 | 最小权限 | 默认只读仓库；仅 publish 允许写包；部署任务不请求额外权限 |
| SEC-002 | 不信任 PR 代码 | PR 无发布与部署任务，不使用特权 PR 触发器 |
| SEC-003 | 不携带应用凭据 | 构建上下文沿用显式允许列表；构建只注入非敏感标识 |
| SEC-004 | 隔离发布凭据 | 发布任务不检出或执行项目代码；只使用平台短期令牌 |
| SEC-005 | 保持运行镜像边界 | 最终镜像仅含构建产物、生产依赖与迁移，使用非 root 用户 |
| SEC-006 | 部署钩子只以机密形式存在 | URL 仅来自仓库机密，绝不写入工作流、日志或产物；日志中由平台掩码 |

### 性能需求

| ID | 指标 | 目标 | 度量方式 |
| --- | --- | --- | --- |
| PERF-001 | 校验与镜像构建并行 | 无相互等待 | 运行任务时间线 |
| PERF-002 | 缓存复用 | 依赖按平台及锁文件隔离，镜像复用构建层 | 缓存命中日志 |
| PERF-003 | 过时 PR 运行 | 新运行取消同一 PR 的旧运行 | 两次 PR 更新的运行状态 |
| PERF-004 | 重复构建 | 每次运行只构建一次容器镜像 | 发布日志不含重新构建 |

## 输入/输出契约

- 输入：触发事件、Git 引用、完整提交 SHA、仓库源码、依赖锁文件及 Dockerfile。
- 镜像名称：`ghcr.io/<owner>/<repository>`，自动转为小写。
- 标签：`sha-<完整 SHA>`；主分支另有 `main`、`latest`；版本另有原始 `v*` 标签。
- 非发布事件生成元数据并验证构建，但不上传发布产物或推送标签。
- 中间产物：仅本次运行可消费的镜像归档，保留一天，不压缩。
- 最终输出：GHCR 镜像及运行摘要中的标签和 digest；`main` 推送的真实发布另有一次部署钩子调用，其结果为外部平台接受与否。

### 密钥与变量

| 类型 | 名称 | 用途 | 作用范围 |
| --- | --- | --- | --- |
| 自动令牌 | GITHUB_TOKEN | GHCR 登录及写包 | publish |
| 仓库机密 | DEPLOYMENT_HOOK_URL | 外部部署平台的部署钩子 URL | deploy |
| 非敏感输入 | 提交 SHA | 诊断构建标识 | image |

无需额外 PAT 或应用密钥。未配置 `DEPLOYMENT_HOOK_URL` 时 `main` 推送的部署任务明确失败，不静默跳过、不回退到其他触发器。组织或既有包的访问策略仍可能阻止发布。

## 执行约束

- verify / image / publish / deploy 的超时分别为 20 / 30 / 15 / 5 分钟。
- 同一工作流、同一 Git 引用使用一个并发组；只有 PR 会主动取消正在运行的旧任务。`main` 的运行因此串行，不会有两次部署任务并发。平台仍可能替换排队中的旧运行，不保证逐个发布每次推送。
- 部署钩子调用最多 60 秒；仅当平台以 `405` 明确拒绝该 HTTP 方法时才改用另一方法，其余非 2xx 一律失败，不盲目重试。
- 托管运行器需访问代码托管、依赖仓库、基础镜像仓库、构建缓存、产物存储、GHCR 及部署钩子主机。
- 当前只承诺 Linux AMD64，不包含 ARM64 或多架构清单。

## 错误处理策略

| 错误类型 | 响应 | 恢复动作 |
| --- | --- | --- |
| 安装、检查、测试或构建失败 | 运行失败，不发布、不部署 | 修复后重新运行 |
| 产物上传或下载失败 | 发布失败或跳过，部署不发生 | 检查产物服务并重新运行；过期后需重跑构建 |
| GHCR 权限或网络失败 | 发布任务失败，部署不发生 | 修复权限或网络后重新运行 |
| 部署钩子未配置 | 部署任务失败并明确指出缺少机密 | 由仓库维护者设置 `DEPLOYMENT_HOOK_URL` |
| 部署钩子不可达或返回非 2xx | 部署任务失败；镜像已发布但未部署 | 人工确认平台状态后再决定是否重跑，不能盲目重复触发 |
| 部署已触发但平台随后失败 | 工作流无法感知；平台状态才是事实 | 按部署手册排查；工作流不宣称部署成功 |
| 部分标签推送成功 | 保留已经写入的标签，不宣称发布原子性 | 重跑同次发布；生产仍按 digest 固定版本 |

## 质量门禁

类型检查、静态检查、单元测试、应用构建和真实容器构建均不得绕过。当前不包含镜像漏洞扫描门禁，也不声称镜像无已知漏洞。部署钩子不构成质量门禁：它只在门禁全部通过后触发。

## 监控与可观测性

- 任务日志用于检查失败、缓存命中和耗时；发布摘要提供标签和 digest；部署任务只输出钩子返回的 HTTP 状态，不输出 URL。
- 通知与日志保留沿用仓库设置；不新增告警系统。
- 无历史运行基线，不承诺节省比例。缓存预计减少重复下载和编译；镜像归档会增加一次上传与下载开销。

## 集成点

- GitHub Actions：执行、令牌、缓存及临时产物存储。
- GHCR：保存应用镜像；包可见性由仓库维护者管理，不自动公开。
- 外部部署平台（Dokploy）：接收部署钩子并重建生产容器。该平台由此获得生产容器生命周期控制权，不能再与宿主机部署 CLI 或另一个自动部署任务同时替换同一服务。
- 部署 CLI：操作者仍可按 digest 拉取镜像并显式执行安装、更新或回滚。启用部署钩子不取消人工路径，但二者必须在发布协调上串行。

## 合规与治理

所有工作流修改按仓库代码审查策略处理。发布授权取决于谁能修改 main、创建版本标签、触发运行及读取仓库机密；分支与标签保护由维护者配置。应用凭据始终只在运行时注入。**部署钩子机密对任何能触发 `main` 工作流的贡献者可用，因此它不得与数据库、维护令牌或平台管理凭据共用。**

## 边界情况与例外

| 场景 | 预期行为 | 验证方式 |
| --- | --- | --- |
| Fork PR | 仅校验，不登录 GHCR、不部署 | PR 运行图及日志 |
| 大写 owner/repository | 镜像名称转为小写 | 元数据输出 |
| 手动运行非主分支 | 构建但不发布、不部署 | 条件检查及运行图 |
| 预发布 v 标签 | 发布原标签，不覆盖 latest，不部署 | 元数据输出及运行图 |
| 同一提交重跑 | 可覆盖 SHA 标签；标签不等于不可变引用；会再次触发部署 | 比较 digest；生产固定 digest |
| 未配置部署钩子机密 | 发布仍完成，部署任务失败并说明原因 | 运行日志中的明确错误 |
| 部署钩子以 405 拒绝 POST | 改用 GET 重试一次 | 部署任务日志 |
| 未授权的既有 GHCR 包 | 明确失败，不回退到其他仓库 | 发布日志 |

## 验证标准

- VLD-001：工作流通过语法、表达式、权限与依赖关系检查。
- VLD-002：真实 Linux AMD64 镜像可构建、导出、加载，两个运维入口的只读检查返回一致构建标识。
- VLD-003：GitHub 实际运行确认授权事件推送 GHCR，PR 不推送；本地验证不能替代此项。
- VLD-004：GitHub 实际运行确认 `main` 推送触发一次部署钩子调用，且 `v*` 标签与 PR 不触发。
- PERF-005：缓存及并发收益须以实际运行时间线测量，不由配置推断为已实现的节省。
